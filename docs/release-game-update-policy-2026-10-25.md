# 游戏更新与兼容发布流程

本包的兼容单位是已验证的游戏模块组合，不是“永远支持终末地”的通用开关。`Endfield.exe`、`UnityPlayer.dll`、`OneChannelLC.dll`的固定SHA-256以及发行者检查、挂接点字节和FSR着色器身份共同限定支持范围。

## 用户看到“版本尚未适配”时

1. 确认选择的是包含`Endfield.exe`的游戏目录，检查文件完整性。
2. 如果游戏模块刚更新，请等待本项目的适配包；也可自行使用官方启动器。独立启动器不会自动回退到官方路线。
3. 不要手工替换哈希、删除检查或把旧DLL复制进新游戏目录。提交问题时只提供必要的版本、模块哈希、错误状态和操作步骤，检查日志后再分享。

资源／活动更新未必改变三个模块，因此不必把每次资源更新都当成不兼容；实际以校验和运行时状态为准。

## 维护者发布步骤

1. 保留上一版已审核包及校验清单。取得新游戏模块身份，检查签名并与上一组合对照，记录SHA-256、版本信息和变化原因。
2. 若受校验模块变化，用开发构建重新确认相关挂接点、磁盘／内存字节、Unity限帧入口、FSR回调与七个核心着色器身份，不能只更新哈希放行。
3. 验证XeSS输入、尺寸、资源状态及实际输出，确认FSR核心持续停算；检查补帧倍率与所选容量一致。重用已有工具，不默认在发行版启用深度诊断。
4. 在同一候选中执行编译、CPU／产品回归、发行配置检查和Vulkan加载自测，再做一轮实际游戏短测：补帧关／开、地图／菜单、拍照、窗口恢复和正常退出。新增挂接点需单独验证。
5. 清洁安装时不应存在`game-path.txt`，首次运行必须先选择／验证游戏目录。检查状态包含`build_flavor=release-minimal`，没有开发明细事件。
6. 重新打包并核对许可证、对应源码、路径清理和校验值。发布说明列出实际验证的模块组合、工具链、功能范围、已知问题和验收记录。
7. 由项目所有者确认源码检查点、标签和许可证后，再公开发布。未经确认不提交、不打标签、不推送。

不承诺游戏更新后的固定适配时限；验证未完成时保留拒绝接管行为，完成后发布新的候选／版本。已有版本不在线自动放宽校验。
